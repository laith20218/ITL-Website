نظرة عامة 01

١. نظرة عامة على الموقع

موقع ITL هو موقع تعريفي فاخر لفريق متخصص في خدمات البحث العلمي والترجمة والتصميم والإنتاج السمعي البصري والتدريب والتسويق الرقمي والطباعة. بُني الموقع على أحدث التقنيات العالمية لضمان الأداء العالي والأمان وتجربة مستخدم استثنائية، مع التزام كامل بالهوية البصرية الفاخرة للفريق (أسود + ذهبي) ودعم عربي كامل بنظام RTL.

١.١ المميزات الرئيسية

  • صفحة رئيسية فاخرة — Hero مع شعار مخصص SVG، إحصائيات، اقتباس مميز، أقسام خدمات ومن نحن ومدونة وتواصل.
  • سبع خدمات تفصيلية — كل خدمة لها صفحة مستقلة على /services/[slug] مع مميزاتها وخطوات العمل ومقالات ذات صلة.
  • مدونة معرفية — مقالات قابلة للبحث والفلترة حسب الفئة، مع نظام عرض كامل في نوافذ منبثقة.
  • نموذج تواصل ذكي — يختار الخدمة المطلوبة، يحفظ الرسائل في قاعدة البيانات، يظهر إشعارات نجاح.
  • نظام مصادقة كامل — تسجيل/دخول/خروج بـ JWT cookie، تشفير scrypt لكلمات المرور، جلسات لمدة 7 أيام.
  • لوحة تحكم احترافية — إدارة كاملة للخدمات والمقالات والرسائل مع إحصائيات حية.
  • وضع ليلي/نهاري — تبديل فوري مع حفظ التفضيل في المتصفح.
  • تصميم متجاوب 100% — يعمل على الجوال واللوحي والحاسب بسلاسة.
  • تحسين محركات البحث (SEO) — Meta tags ديناميكية لكل صفحة، روابط نظيفة، خريطة موقع.

١.٢ الجمهور المستهدف

الموقع موجه لـ: الباحثين الأكاديميين الذين يحتاجون مساعدة في الأبحاث والترجمة، الشركات التي تبحث عن تصميم هوية أو إنتاج محتوى بصري، المؤسسات التي تحتاج تدريب لموظفيها، الطلاب الذين يطلبون مشاريع تخرج أو رسائل. الأسلوب الفاخر يطمح لجذب عملاء يبحثون عن جودة عالية ومستعدون للدفع مقابلها.

٢.٢ نمط البنية (Architecture Pattern)

المشروع يتبع نمط Server-First with Client Islands — معظم الصفحات Server Components تُعرض على الخادم لسرعة أعلى، والمكونات التفاعلية فقط ('use client') تُحمَّل على المتصفح. هذا يقلل حجم JavaScript المرسلة ويحسّن SEO بشكل كبير.

  • Server Components — صفحات الخدمات، صفحات لوحة التحكم (تقرأ البيانات مباشرة من DB).
  • Client Components — النماذج، القوائم المنسدلة، نوافذ التعديل، البحث.
  • API Routes — Server-side endpoints على /api/* للعمليات الحساسة.

٢.٣ تدفق المصادقة (Authentication Flow)

المستخدم يملأ النموذج
       ↓
Client → POST /api/auth/login (email, password)
       ↓
Server: db.user.findUnique({ email })
       ↓
verifyPassword(password, user.password)  // scrypt + timing-safe compare
       ↓
createToken({ userId, email, name, role })  // HMAC-SHA256 signed JWT
       ↓
cookies().set('itl_auth', token, { httpOnly: true, maxAge: 7d })
       ↓
Response → Client updates UI (AuthProvider context)

قاعدة البيانات 04

٤. المخطط البرمجي لقاعدة البيانات

قاعدة البيانات مصممة بـ Prisma ORM. محليًا نستخدم SQLite (ملف واحد بسيط)، وفي الإنتاج سننتقل لـ PostgreSQL عبر Neon (مجاني). المخطط هو نفسه — فقط نغيّر provider في prisma/schema.prisma.

٤.١ المخطط الكامل

// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"          // غيّر لـ "postgresql" في الإنتاج
  url      = env("DATABASE_URL")
}

model User {
  id        String   @id @default(cuid())
  name      String
  email     String   @unique
  password  String                   // scrypt hash: salt:hash
  phone     String?
  role      String   @default("user")  // "user" | "admin"
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Service {
  id          String   @id @default(cuid())
  slug        String   @unique       // URL: /services/[slug]
  title       String
  category    String                  // للفلترة
  description String
  icon        String                  // اسم Lucide icon
  features    String                  // JSON array as string
  order       Int      @default(0)    // ترتيب العرض
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

model Article {
  id          String   @id @default(cuid())
  slug        String   @unique
  title       String
  excerpt     String                  // ملخص قصير
  content     String                  // محتوى كامل
  category    String
  author      String   @default("فريق ITL")
  imageUrl    String?
  tags        String?                 // مفصولة بفواصل
  published   Boolean  @default(true)
  viewCount   Int      @default(0)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

model ContactMessage {
  id        String   @id @default(cuid())
  name      String
  email     String
  phone     String?
  subject   String
  message   String
  service   String?                  // اسم الخدمة المطلوبة
  status    String   @default("new")  // new|read|replied|archived
  createdAt DateTime @default(now())
}

٤.٢ العلاقات بين الجداول

المخطط الحالي بسيط بدون علاقات صريحة (لا foreign keys). هذا متعمد لتبسيط البنية — كل جدول مستقل. لو أردت توسيع المستقبل (مثل ربط المقالات بالمؤلفين، أو الرسائل بالمستخدمين)، أضف:

// إضافة علاقات مستقبلية (اختياري)
model Article {
  ...
  authorId  String
  author    User     @relation(fields: [authorId], references: [id])
}

model User {
  ...
  articles  Article[]
}
⚠️ ملاحظة هامة للإنتاج

SQLite ممتاز للتطوير المحلي لكنه لا يعمل على Vercel لأن Vercel بيئة serverless بدون نظام ملفات دائم. لذلك سنستخدم PostgreSQL مجاني من Neon (سنشرح في الفصل ٦).

النشر — Neon Database 06

٦.٢ إنشاء قاعدة بيانات PostgreSQL مجانية على Neon

Neon هو خدمة PostgreSQL سحابية مجانية بالكامل للمشاريع الصغيرة (0.5GB تخزين، مشروطة بالاستخدام). أفضل من SQLite للإنتاج لأنها تبقى دائمة ولا تُفقد عند كل نشر.

1

التسجيل في Neon

ادخل إلى neon.tech → اضغط "Sign up" → اختر "Continue with GitHub" (أو Google أو email). أكّد بريدك.

2

إنشاء مشروع جديد

من لوحة التحكم اضغط "New Project". اختر:

  • Name: itl-website
  • Database name: itl
  • Region: الأقرب لجمهورك (Frankfurt لأوروبا، Singapore لآسيا، US East لأمريكا)
  • Postgres version: 16 (افتراضي)

اضغط "Create project".

3

نسخ رابط الاتصال

بعد إنشاء المشروع، ستظهر لك شاشة "Connection Details". انسخ الرابط الذي يبدأ بـ postgresql:// — سيكون شبيهًا بـ:

postgresql://itl_owner:npg_Xk7pM...@ep-cool-dawn-12345.us-east-2.aws.neon.tech/itl?sslmode=require

احتفظ بهذا الرابط سرًا — سنستخدمه في Vercel.

4

تعديل مخطط Prisma لـ PostgreSQL

افتح prisma/schema.prisma وغيّر الـ provider:

datasource db {
  provider = "postgresql"     // ← غيّر من sqlite
  url      = env("DATABASE_URL")
}

ثم commit + push:

git add prisma/schema.prisma
git commit -m "Switch to PostgreSQL for production"
git push
5

إنشاء الجداول محليًا للاختبار (اختياري)

لتجربة PostgreSQL محليًا قبل النشر:

# حدّث DATABASE_URL في .env مؤقتًا لرابط Neon
# ثم شغّل:
bun run db:push
bun run scripts/seed.ts

# ثم أعده لـ SQLite محليًا إن أردت:
# DATABASE_URL="file:./db/custom.db"
💡 ميزة Neon

Neon يدعم "branching" — يمكنك إنشاء branch من قاعدة البيانات للتجربة دون لمس البيانات الحقيقية. كذلك Scale-to-zero: قاعدة البيانات تنام عند عدم الاستخدام لتوفير الموارد، وتستيقظ خلال ثانية عند أول طلب.

  • Google Workspace — 6$/شهر لكل حساب، احترافي وكامل لكن مدفوع.
بعد إعداد البريد

حدّث بريد التواصل في src/components/itl/contact.tsx و footer.tsx من info@itl-team.com لبريدك الفعلي. كذلك في src/app/services/[slug]/page.tsx. اعمل commit + push وسيتحدث الموقع تلقائيًا.

لوحة تحكم المشرف 08

٨. لوحة تحكم المشرف — الدليل التفصيلي

لوحة التحكم هي قلب إدارة الموقع. من خلالها تتحكم في كل المحتوى دون لمس الكود. كل ما تحتاجه متصفح إنترنت وكلمة مرور المشرف.

٨.١ الدخول إلى لوحة التحكم

  1. افتح المتصفح وانتقل إلى https://your-domain.com/admin-login
  2. أدخل البريد: demo@itl.com وكلمة المرور: demo1234
  3. اضغط "دخول لوحة التحكم"
  4. سيتم نقلك تلقائيًا إلى /admin/dashboard
⚠️ إجراء أمني ضروري بعد النشر

كلمة المرور الافتراضية demo1234 معروفة للعامة. يجب تغييرها فور النشر. الطريقة: اشترك بمستخدم جديد عبر /api/auth/register ببريد مختلف، ثم في Neon SQL Editor نفّذ: UPDATE User SET role='admin' WHERE email='your-new-email' و DELETE FROM User WHERE email='demo@itl.com'.

٨.٢ الصفحة الرئيسية للوحة (Dashboard)

تعرض نظرة سريعة على حالة الموقع:

  • 5 بطاقات إحصائيات (قابلة للنقر للانتقال للقسم): الخدمات، المقالات، إجمالي الرسائل، رسائل جديدة (تومض ذهبيًا)، المستخدمون.
  • آخر 5 رسائل — اسم المرسل، موضوع، تاريخ، حالة (جديد/مقروء).
  • الطلبات حسب الخدمة — مخطط أعمدة أفقية يوضح أي الخدمات تطلب أكثر، يساعدك على التركيز عليها.
  • آخر 5 مقالات — جدول بـ title, category, status, viewCount, createdAt.

٨.٣ إدارة الخدمات

إضافة خدمة جديدة

  1. اذهب لـ /admin/services → اضغط "خدمة جديدة"
  2. املأ الحقول:
    • عنوان الخدمة — الاسم الظاهر للزوار (مثال: "خدمة ترجمة جديدة")
    • المعرّف (slug) — أحرف لاتينية بلا مسافات، يحدد الرابط: /services/new-translation
    • الفئة — للتصنيف والفلترة (مثال: "الترجمة")
    • الأيقونة — اختر من القائمة (GraduationCap, Languages, Palette, Clapperboard, Users, Megaphone, Printer)
    • الوصف — فقرة تعريفية (تظهر في الصفحة الرئيسية + صفحة التفاصيل)
    • المميزات — سطر لكل ميزة (مثال: "ترجمة أكاديمية")، الأسطر الفارغة تُحذف تلقائيًا
    • الترتيب — رقم (الأصغر يظهر أولًا)
  3. اضغط "حفظ" → ستظهر الخدمة فورًا في الموقع

تعديل / حذف خدمة

  • اضغط "تعديل" على الخدمة → عدّل الحقول → احفظ
  • للحذف: اضغط أيقونة سلة المهملات → أكد الحذف (لا يمكن التراجع!)

٨.٤ إدارة المقالات

نفس فكرة الخدمات لكن مع حقول إضافية:

  • الملخص — يظهر في بطاقة المقال (2-3 أسطر)
  • المحتوى — النص الكامل، استخدم سطرًا فارغًا للفصل بين الفقرات
  • الكاتب — اسم الكاتب (افتراضي: فريق ITL)
  • الوسوم — كلمات مفتاحية مفصولة بفواصل (مثال: "ترجمة,أكاديمي,لغات")
  • الحالة — "منشور" (مرئي) أو "مسودة" (محفوظ غير منشور)

٨.٥ صندوق الرسائل

  • فلاتر: الكل / جديدة / مقروءة / تم الرد / مؤرشفة — مع عدّاد لكل فلتر
  • اضغط رسالة لفتحها — تُعلَّم تلقائيًا كـ "مقروءة"
  • من النافذة: رد عبر البريد (يفتح برنامج البريد جاهزًا)، وضع كـ تم الرد، أرشفة، حذف
💡 أفضل ممارسات سير العمل

افتح الرسائل الجديدة يوميًا → ارد على المهملة في نفس اليوم → ضعها في "تم الرد" → أرشف القديمة شهريًا. هذا يبني صورة احترافية ويزيد فرص تحويل الاستفسارات لعملاء.

الصيانة والأمان 09

٩. الصيانة والنسخ الاحتياطي والأمان

الموقع كأي نظام حيوي — يحتاج صيانة دورية. هذا الفصل يغطي أهم الممارسات لإبقائه سريعًا وآمنًا ومستمرًا.

٩.١ النسخ الاحتياطي التلقائي

Neon Free يوفر نسخًا احتياطيًا تلقائيًا لمدة 7 أيام (Point-in-Time Recovery). للنسخ اليدوي:

# تثبيت Vercel CLI إن لم يكن مثبتًا
npm i -g vercel

# سحب متغيرات البيئة من Vercel
vercel env pull .env.backup

# تصدير قاعدة البيانات إلى ملف SQL
npx prisma db pull     # يحلّل البنية
npx pg-dump "$DATABASE_URL" --file backup-$(date +%Y%m%d).sql

# رفع النسخة إلى Google Drive أو Dropbox (يدويًا)

٩.٢ تغيير كلمة مرور المشرف

الطريقة الأبسط حاليًا هي عبر Neon SQL Editor مباشرة. أولاً، ولّد hash جديد بـ Node:

# في terminal محليًا
node -e "
const {scryptSync, randomBytes} = require('crypto');
const pw = 'new-password-here';
const salt = randomBytes(16).toString('hex');
const hash = scryptSync(pw, salt, 64).toString('hex');
console.log(salt + ':' + hash);
"

انسخ الناتج، ثم في Neon SQL Editor:

UPDATE User
SET password = 'الناتج_المنسوخ'
WHERE email = 'demo@itl.com';

٩.٣ تحديث الموقع

عند إضافة ميزة أو إصلاح خطأ:

  1. اختبر محليًا: bun run dev
  2. commit: git add . && git commit -m "وصف التغيير"
  3. push: git push origin main
  4. Vercel سيعيد النشر تلقائيًا خلال 2-3 دقائق
  5. تحقق من الموقع المنشور + UptimeRobot للتأكد

٩.٤ تحديث التبعيات الأمنية

شهريًا، حدّث الحزم لأحدث إصدارات آمنة:

# فحص الثغرات الأمنية
bun audit            # أو npm audit

# تحديث الحزم الآمن (دون كسر)
bun update

# تحديث Major versions (بحذر، اختبر بعد كل واحد)
bun add next@latest react@latest react-dom@latest

# اختبر قبل الـ push
bun run lint
bun run dev

٩.٥ ممارسات أمان أساسية

  • لا تشارك كلمة مرور المشرف — أنشئ حسابات منفصلة لكل عضو فريق
  • فعّل المصادقة الثنائية (2FA) على GitHub و Vercel و Cloudflare و Neon
  • راقب رسائل التواصل شهريًا — احذف الرسائل المزعجة أو المشبوهة
  • لا ترفع ملف .env إلى GitHub — تأكد دائمًا أنه في .gitignore
  • استخدم كلمات مرور قوية — 12+ حرفًا، أحرف كبيرة وصغيرة وأرقام ورموز
  • راقب سجلات Vercel أسبوعيًا — للكشف عن محاولات اختراق أو أخطاء
  • فعّل Vercel DDoS Protection — مفعّل افتراضيًا في الباقة المجانية عبر Cloudflare

٩.٦ تحسين الأداء

  • الصور: استخدم تنسيق WebP بدلاً من JPEG/PNG، وحجمها لا يتجاوز 200KB للصورة الواحدة
  • الخطوط: نستخدم Cairo + Amiri من Google Fonts مع display: swap لتحميل أسرع
  • Code Splitting: Next.js يقسم الكود تلقائيًا لكل صفحة
  • CDN: Cloudflare يخزّن الأصول ثابتة (CSS, JS, الصور) في 200+ موقع عالمي
  • Image Optimization: Next.js يحسّن الصور تلقائيًا (sharp مثبت)
